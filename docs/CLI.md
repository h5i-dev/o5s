# o5s CLI reference

Generated by `scripts/gen-cli-doc.sh` from `o5s --help`; regenerate after changing the CLI.
The CLI is plumbing over the domain-agnostic core. How a put is stored comes from namespace profiles
(`init --profile/--namespace`, then `put --for-name`), and domain protocols are served by the server's fronts.

Exit codes: 0 ok, 1 error, 2 not found/absent, 3 OCC conflict, 4 forbidden (namespace rule or promotion policy), 5 unauthorized.

```text
Content-addressed repository: put/get objects, move names with OCC

Usage: o5s [OPTIONS] <COMMAND>

Commands:
  init       Create a repository
  put        Store a file (or stdin with `-`), print its hash. How it is stored comes from the namespace profile of `--for-name` (chunker, derive from the name's current object, the profile's front); without it, the store's defaults. Works with `--remote` too. Doesn't move any name
  get        Write an object (or a byte range of it) to stdout or a file
  search     Search names and metadata: full text (all words must match), or `--prefix P` for names under a prefix. Prints `<hash> <names...>`
  retention  Apply the profiles' retention (keep_versions, only_if_regenerable): delete old versions' names so GC can collect them. Local only
  size       Print an object's size in bytes
  resolve    Print `<hash> <version>` for a name
  replace    Compare-and-swap a name
  update     Atomically update several names (one OCC transaction): `NAME=HASH` sets, `NAME=-` deletes. Every target must be in the read set (`--expect`)
  delete     Delete a name (OCC). Immutable/released names can't be deleted
  refs       List refs under a prefix
  ns         Namespace rules
  name       File paths as names (needs no repository): the canonical, reversible encoding
  flush      Seal open packs (make written objects durable and visible)
  stat       Repository statistics
  fsck       Verify every stored object (CRC + content hash) and every ref. Exit 1 on problems
  prov       Provenance: record derivations; lineage, impact and why of a HASH or NAME
  attest     Signed attestations (in-toto Statement v1 in DSSE envelopes) about a HASH or NAME
  promote    Promote: move DST to the object SRC names, if the policy given by the flags holds (one OCC transaction, recorded as a `promote` provenance record). With --remote, the server's `[[promotion]]` policy applies instead (and the policy flags are refused)
  gc         Run whichever garbage-collection phases are due (plan → sweep → delete). Safe with concurrent writers. Run it periodically (e.g. from cron). Roots are the current refs; objects are treated as opaque
  help       Print this message or the help of the given subcommand(s)

Options:
  -C, --repo <REPO>      Repository directory [env: O5S_REPO=] [default: .]
      --remote <REMOTE>  Talk to a o5s server instead of a local repository (e.g. <https://o5s.example.com>) [env: O5S_REMOTE=]
      --token <TOKEN>    Bearer token for --remote [env: O5S_TOKEN]
  -h, --help             Print help
  -V, --version          Print version
```

## `init`

```text
Create a repository

Usage: o5s init [OPTIONS]

Options:
      --chunk-threshold <CHUNK_THRESHOLD>
          Objects at least this large are chunked (bytes)
      --pack-cap <PACK_CAP>
          Seal open packs at this size (bytes)
      --zstd-level <ZSTD_LEVEL>
          zstd level for pack records (0 = off)
      --grouped-zstd-level <GROUPED_ZSTD_LEVEL>
          zstd level for byte-grouped records (record codec 2, used when a put carries a grouping width; default 6)
      --refs-on-backend
          Store refs as a create-only log on the object backend instead of a local journal (lets several hosts write one repository on shared storage)
      --chunk <PREFIX=CHUNKER>
          Chunker for a namespace, as PREFIX=CHUNKER (fastcdc or xet), e.g. `--chunk models/=xet`. Repeatable; the longest matching prefix wins. Used by `put --for-name`
      --chunk-default <CHUNKER>
          Chunker for everything else (default fastcdc)
      --profile <NAME=SPEC>
          A domain profile, as NAME=key:value,... with keys front, chunker, derive (none|previous), keep_versions (N) and only_if_regenerable. Example: `--profile weights=front:safetensors,derive:previous`. Repeatable
      --namespace <PREFIX=PROFILE>
          Assign a profile to a name prefix, as PREFIX=PROFILE (e.g. `--namespace models/=weights`). Repeatable; longest prefix wins
      --read-verify <strict|eof>
          Default read verification: "strict" (default) or "eof" (see `get --read-verify`)
      --allow-eof-reads
          Let individual reads ask for `--read-verify eof`
  -h, --help
          Print help
```

## `put`

```text
Store a file (or stdin with `-`), print its hash. How it is stored comes from the namespace profile of `--for-name` (chunker, derive from the name's current object, the profile's front); without it, the store's defaults. Works with `--remote` too. Doesn't move any name

Usage: o5s put [OPTIONS] [FILE]

Arguments:
  [FILE]  [default: -]

Options:
      --for-name <NAME>       Apply NAME's namespace profile (see `init --profile/--namespace`)
      --encoding <KEY=VALUE>  Low-level override of the encoding, as KEY=VALUE (repeatable): `chunker=ID` (fastcdc|xet), `group-width=N`, `derive-from=HASH`, `patch=xor|xor-anchored` (with derive-from; default xor-anchored). Storage only, never the hash
  -h, --help                  Print help
```

## `get`

```text
Write an object (or a byte range of it) to stdout or a file

Usage: o5s get [OPTIONS] <HASH>

Arguments:
  <HASH>  

Options:
      --range <RANGE>             Byte range `START..END` (end exclusive)
  -o, --output <OUTPUT>           
      --read-verify <strict|eof>  Verification for this read: "strict" (every chunk's hash before its bytes are returned) or "eof" (record CRCs, plus the whole-object hash at EOF, so CRC-valid crafted bytes can be written before the error). "eof" needs `[read] allow_eof`. Default: the repository's setting
  -h, --help                      Print help
```

## `gc`

```text
Run whichever garbage-collection phases are due (plan → sweep → delete). Safe with concurrent writers. Run it periodically (e.g. from cron). Roots are the current refs; objects are treated as opaque

Usage: o5s gc [OPTIONS]

Options:
      --grace <GRACE>         Minimum time between phases (e.g. 30m, 1h, 2d). Must be at least 10m unless --unsafe-short-grace is given [default: 1h]
      --unsafe-short-grace    Allow a grace period under 10 minutes. Only safe with no active writers
      --dry-run               Report what would happen without changing anything
      --no-similarity-repack  Copy live records verbatim instead of laying them out by content similarity (the default, also settable with `[gc] similarity_repack`)
      --repack-all            Repack every pack, even fully live ones (recompresses records written at a fast ingest level, e.g. `init --zstd-level 1`, into similarity frames)
  -h, --help                  Print help
```
